The help docs at /docs belong to the editors. A release can bring a new doc, or a change to one you already have, but it never publishes a doc or changes one.

## New docs

A release that adds a feature brings its doc as a **draft** under **Help → Docs**. It's a first draft, with the facts in place. Rewrite it in our voice, move it where it belongs in the tree, then publish it. Until then, it's not on /docs and it's not in the bell.

## Suggestions

When a release changes a feature that a doc describes, the doc stays as you wrote it. Instead, the release adds a **suggestion** beside the doc:

- **What changed**: a sentence from the developers on the change.
- **Changes to the repo's copy**: the lines of the developers' copy of the doc that changed. Added lines are green, removed lines are red and struck through.
- **Pictures**: any new or changed pictures, already uploaded to Media.

The bell tells editors about open suggestions. Each doc lists its own under **Suggestions**, and **Help → Suggestions** lists them all.

To work one in:

1. Open the suggestion and read what changed.
2. Open the doc and change it in your own words. The suggestion shows what changed, not the words to use.
3. Back on the suggestion, set **Status** to **Done** and save. Set it to **Dismissed** instead if the doc doesn't need to change.

If another change arrives while a suggestion is still open, it's added to that suggestion, so you read one combined change.
